# スケジュール管理スキル

hayator の予定を Google Calendar で扱うときの標準手順。スケジュール担当はこれに従う。

## 前提

| 項目 | 値 |
|------|-----|
| メインカレンダー | `ishishinokai@gmail.com`（表示名「hayator」） |
| タイムゾーン | Asia/Tokyo（JST, +09:00） |
| デフォルト所要時間 | 1時間（指定がなければ） |

## 予定を登録する手順

1. 依頼から **件名・日付・開始時刻・所要時間・場所/リンク・参加者**を読み取る
2. 不足を補う
   - 所要時間の指定なし → **1時間**
   - 日付があいまい（曜日だけ等）→ 直近の該当日を採用し、報告時に日付を明示
3. `create_event` を呼ぶ
   - `calendarId`: `ishishinokai@gmail.com`
   - `startTime` / `endTime`: `YYYY-MM-DDTHH:MM:SS+09:00` 形式
   - `timeZone`: `Asia/Tokyo`
4. 同じ時間帯に別予定があれば、ネガティブ表現を避けて中立に知らせる
   - 例：「同時間帯に〇〇があります。どちらを優先しますか？」
5. 完了後、下の**報告フォーマット**で報告する

## 予定を変更・削除する手順

1. `list_events` で対象を特定（件名・日時で照合）
2. 複数候補があれば、どれか確認してから実行
3. `update_event` / `delete_event` を実行
4. 削除は実行前に対象を一度提示して確認する

## 空き時間を探す手順

- `suggest_time` または `list_events` で該当期間を取得し、空きスロットを提案する

## 報告フォーマット（必ず使う）

```
✅ 登録しました
・件名：〇〇
・日時：M/D(曜) HH:MM〜HH:MM
・カレンダー：hayator
・リンク：<htmlLink>
```

## 接続が不安定なとき

- カレンダーのツールが読み込めない場合は、**依頼内容を控えて再試行**する
- 成功したか確認してから完了報告する（**二重登録を避ける**）
- 何度も失敗する場合は、状況を正直に報告し、手動登録の選択肢を案内する

## やってはいけないこと

- ネガティブ表現（相性が悪い・向いていない 等）
- hayator の確認なしに、予定を他人と共有・公開すること
- 参加者のメールアドレスを推測で追加すること
