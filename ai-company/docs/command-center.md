# 司令塔（Command Center）— つばさが全体を動かす仕組み

hayator は **つばさ1人に指示を出すだけ**。つばさが「どのツール（担当部署）にやらせるか」を判断し、
そのツール用の**作業指示書**を作って渡す。各ツールが実行し、結果をつばさが集約して報告する。

---

## 正直な前提（ここが設計の土台）

つばさは Cursor / codex / エルメスエージェント などを**直接ボタン操作できない**（別アプリのため）。
だから「全部を動かす」は、現実的には次の3レベルで実現する。

| レベル | 仕組み | 現状 |
|--------|--------|------|
| **L1 作業指示書方式** | つばさが用件を受け、担当ツール用の指示書(プロンプト)を生成 → hayator が各ツールに貼る | ✅ **今すぐ可能** |
| **L2 掲示板方式（半自動）** | つばさが GitHub の Issue / タスクファイルに指示を書き、各ツールがそれを読んで実行 | 🟡 段階導入 |
| **L3 直結（完全自動）** | 各ツールを API / MCP で直結し、つばさが直接起動 | 🔵 将来（要開発） |

→ まず **L1 で運用開始**。慣れたら L2 に上げて手作業を減らす。

## 担当マップ（振り分け表）

| 用件のジャンル | 担当ツール | 経由モデル | 対象プロジェクト | 指示書テンプレ |
|----------------|-----------|-----------|------------------|----------------|
| 4コマ制作 / SNS投稿 / スタイル診断 | **Cursor** | Claude Code | おのくん4コマ・X/SNS・AIスタイル診断 | `templates/work-order-cursor.md` |
| レボリンク関連 | **エルメスエージェント** | Grok | レボリンク | `templates/work-order-hermes-grok.md` |
| ファンディング / 診断の実装 | **codex** | Codex | レボファンディング・レボリスト診断 | `templates/work-order-codex.md` |
| レボ各リポの直接コード変更 | **Claude Code** | Claude | revofunding / revolist-diagnosis | （この環境で直接） |
| 予定・メール・資料 | **claude.ai（秘書つばさ）** | Claude | 全社共通 | schedule-intake ほか |

> ⚠️ **秘書タスク（予定・メール・資料）は claude.ai（ブラウザ/アプリ）が主戦場。**
> Claude Code はコネクタ接続が不安定なので、カレンダーは `.ics` 代替になる。理由は operating-rules.md 参照。

## つばさの動き方（L1 の標準フロー）

1. **受ける**：hayator の用件を1文で復唱して確認
2. **振り分ける**：担当マップで担当ツールを決める（複数にまたがる時は分割）
3. **指示書を作る**：そのツール用テンプレに沿って**作業指示書**を出力（下記スキーマ）
4. **渡す**：hayator が指示書を該当ツールに貼って実行
5. **集約する**：結果を受け取り、worklog に記録し、hayator へ定型報告

### 作業指示書スキーマ（共通）

```
【担当ツール】Cursor / codex / エルメス・Grok / Claude Code
【プロジェクト】◯◯
【ゴール】1文で「何が完成すれば成功か」
【前提・入力】参照ファイル・URL・素材
【手順 or 要件】箇条書き
【成果物】ファイル/投稿/PRなど
【完了条件（DoD）】これが満たされたら完了
【報告先】つばさへ：結果・リンク・詰まった点
```

---

## 成長の道（L1 → L2）

- **L2 掲示板方式**では、つばさが各リポジトリに `tasks/` フォルダや GitHub Issue で指示を残す
- 各ツール（Cursor / codex）を「そのリポの tasks を見て実行する」運用にすれば、貼り付けの手間が消える
- まず L1 で型を固め、うまく回り始めたら対象プロジェクトから順に L2 化する
